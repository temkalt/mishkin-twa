# Mishkin TWA — План доведения до продакшена

> Полный план на основе детального анализа фронтенда (`src/`), бэкенда (`server/src/`),
> схемы БД (Prisma), конфигов сборки и деплоя.
> Составлен: 2026-08-11.

---

## 0. Вердикт по готовности

Продукт сделан добротно: аккуратный React 19 + Zustand + Framer Motion, честная
криптовалидация Telegram initData, модель «цены в копейках», ленивая загрузка страниц,
приятные анимации. **Но в текущем виде выкатывать нельзя** — есть критические дыры в
безопасности и рассинхрон схемы БД с миграциями (создание заказов упадёт на «чистой»
Postgres). Плюс деплой описан в двух взаимоисключающих вариантах (Docker c SQLite против
Vercel c Postgres), и Docker-путь сломан.

| Область | Состояние | Готовность |
|---|---|---|
| Функционал (каталог/корзина/заказ/админка) | Работает, логика полная | 75% |
| Безопасность | Есть критические дыры | 40% |
| Корректность деплоя/БД | Рассинхрон, битый Docker-путь | 45% |
| Дизайн/UX | Хорошая база, но недокручено | 70% |
| Надёжность (логи/тесты/мониторинг) | Практически отсутствует | 20% |
| Бизнес-логика e-commerce (склад/оплата/фото) | Пробелы | 50% |

## 1. КРИТИЧЕСКИЕ БЛОКЕРЫ (P0) — без этого в прод нельзя

**1.1. Смена статуса заказа доступна любому пользователю.**
`server/src/routes/orders.ts:208` — `PATCH /api/orders/:id/status` не имеет middleware
`isAdmin`. Любой авторизованный пользователь может пометить чужой заказ как «Доставлен» или
«Отменён». `isAdmin` даже импортирован (строка 3), но не навешан.
→ Добавить `isAdmin` в роут.

**1.2. Публичная утечка `ADMIN_IDS`.**
`server/src/index.ts:57` — эндпоинт `/api/debug-auth` отдаёт список ID администраторов кому
угодно (валидация пропускает запросы без заголовка, см. 1.4).
→ Удалить эндпоинт полностью (или закрыть за `isAdmin` + `NODE_ENV`).

**1.3. Незащищённый `/api/setup-webhook`.**
`server/src/index.ts:31` — любой может переустановить webhook бота.
→ Закрыть секретным токеном или убрать после первичной настройки.

**1.4. `validateTelegram` пропускает запросы без initData.**
`server/src/middleware/validateTelegram.ts:28-38` — при отсутствии заголовка
`x-telegram-init-data` в проде вызывается `next()` без пользователя (не отклоняется).
Итог: `POST /api/orders` дёргается откуда угодно → спам-заказы, мусор в БД.
→ В проде при отсутствии/невалидности initData возвращать 401. Dev-заглушку — только под
`development`.

**1.5. Рассинхрон схемы БД и миграции — заказы упадут на чистой Postgres.**
`schema.prisma` (модель `Order`) содержит `userAddress`, `userPostal`, `deliveryMethod`,
`comment`, `tgUsername`, а миграция `20260804030602_init_pg/migration.sql` этих колонок не
содержит. Прячется тем, что `entrypoint.sh` использует `prisma db push` вместо
`migrate deploy`. Любой нормальный деплой миграциями → 500 при создании заказа.
→ Пересобрать миграции (`prisma migrate dev --name sync_order_fields`), закоммитить,
перейти на `prisma migrate deploy`.

**1.6. Mass-assignment в обновлении товара.**
`server/src/routes/products.ts:106` — `const data = { ...req.body }` летит в `prisma.update`.
→ Явный whitelist полей.

**Удалить до прода:** `/api/debug-auth`, `/api/setup-webhook` (или защитить),
`server/prisma/dev.db`.

## 2. Архитектура деплоя — выбрать ОДИН путь и починить

В репозитории два несовместимых сценария:

- **Vercel** (реальный): фронт `mishkin-twa.vercel.app`, бэк-serverless
  `mishkin-twa-ylrh.vercel.app` (`vercel.json` rewrite `/api`), бот через webhook, БД — Postgres.
- **Docker + nginx** (`docker-compose.yml`, `nginx.conf`, `Dockerfile`): **сломан** — задаёт
  `DATABASE_URL=file:/app/prisma/data/dev.db` (SQLite) при `postgresql` в схеме. Плюс
  `entrypoint.sh` в проде запускает `npx tsx src/index.ts` (dev-рантайм) и
  `prisma db push --accept-data-loss` при каждом старте.

**Рекомендация: зафиксировать Vercel + управляемая Postgres** (Supabase/Neon/Railway),
а Docker привести в порядок для self-hosted или убрать.

Если Vercel:
- Serverless + Telegraf уже корректно (при `process.env.VERCEL` polling выключен, работает webhook).
- Добавить `secret_token` к webhook + проверка заголовка `X-Telegram-Bot-Api-Secret-Token`.
- `prisma migrate deploy` в build-шаге.
- Проверить пул соединений (Neon/Supabase pooler + `DIRECT_URL` для миграций).

Если Docker:
- `DATABASE_URL` на Postgres-сервис (добавить `postgres` в compose), убрать SQLite.
- Собирать TS (`npm run build`), запускать `node dist/index.js`, а не `tsx`.
- Убрать `--accept-data-loss`, перейти на `migrate deploy`.
- Убрать сид из автозапуска прод-контейнера.

## 3. Бэкенд: корректность и надёжность

- **Внедрить Zod** (заявлен в `ARCHITECTURE.md`, но в коде отсутствует). Валидировать тела
  `POST /orders`, `POST/PUT /products`, `POST /promo`, `POST /broadcast`, `POST /channel/post`.
- **Гонка счётчика промокода:** `orders.ts:81` делает `usageCount: promo.usageCount + 1`.
  → `usageCount: { increment: 1 }`, всё в одной `prisma.$transaction`.
- **Рассылка (`users.ts:81`) не переживёт serverless:** последовательный цикл с `sleep(50ms)`
  упрётся в лимит времени. → Батчинг (25–30/раз), очередь/крон, обработка 403 (бот заблокирован).
- **Единообразие админ-прав:** авторизация по `ADMIN_IDS` из env, а `User.isAdmin` в БД не
  используется. Выбрать один источник (проще — env, поле убрать).
- **Мёртвая ссылка `order.user`:** фронт `Admin.tsx:29,474` ждёт `order.user.username`, но API
  не делает `include` (и связи нет — `telegramUserId` не FK). Либо добавить связь `Order → User`
  и `include`, либо убрать обращение (спасает `tgUsername`).
- **HTTP-безопасность:** `helmet`, `compression`, `express.json({ limit: '100kb' })`,
  `express-rate-limit` (на `/orders`, `/promo/validate`, `/users/auth`).
- **Обработчик ошибок:** не отдавать `err.message` наружу в проде.
- **Health-check** `/health` есть — добавить проверку БД.

## 4. Модель данных и бизнес-логика e-commerce

- **Учёт остатков:** сейчас только `inStock: boolean`. Добавить `stock: Int`, списывать в
  транзакции, показывать «осталось N».
- **Онлайн-оплата:** сейчас «менеджер свяжется». Нужен платёж (Telegram Payments / ЮKassa /
  CloudPayments / Robokassa) или явно зафиксировать ручную оплату + статус «Оплачен».
- **Загрузка изображений:** схема поддерживает массив, а админ-форма (`Admin.tsx:662`) — один
  URL строкой. Нужен аплоад (Vercel Blob / S3 / Cloudinary / Supabase Storage) + мультизагрузка.
- **Галерея на карточке товара:** `Product.tsx` показывает только `images[0]`. Свайп-галерея с точками.
- **Пирамида аромата не показывается:** `topNote/heartNote/baseNote` хранятся, но на странице
  товара их нет. Для свечного бренда это ключевой контент — вывести блок «Верх/Сердце/База».
- **Атрибуты товара:** время горения, вес/объём, состав, размеры — вынести из описания в поля.
- **Промокоды:** нет `expiresAt`, минимальной суммы, ограничения «один на пользователя».
- **Доставка:** нет полей стоимости доставки и трек-номера.
- **Пагинация** товаров/заказов (сейчас грузится всё) — заложить `take/skip`.
- **Серверный поиск:** сейчас фильтр только по загруженной категории на клиенте
  (`Catalog.tsx:74`). Поиск по всему каталогу — на бэк.

## 6. Дизайн и UX — как сделать красивее

База хорошая: тёплая палитра (оливковый `#3A5A2A` + песочный `#D4A373`), стеклянная навигация,
shared-layout анимации перелёта фото, shimmer-скелетоны, стаггер. Докрутить:

**6.1. Тёмная тема сейчас сломана.** В `tailwind.config.js` есть `background-dark`,
`darkMode:'class'`, `App.tsx:55` вешает `.dark` — но страницы жёстко прописывают
`bg-background-light`/`text-text-main`, а `.glass-nav` захардкожен светлым rgba.
→ Либо полноценно внедрить (пары `bg-background-light dark:bg-background-dark`, тема-зависимый
`.glass-nav`, `themeParams`), либо честно зафиксировать светлую тему и убрать dark-токены.

**6.2. Нативная интеграция с темой Telegram:** использовать `WebApp.themeParams` / CSS-переменные
(`--tg-theme-*`), задать `setHeaderColor`, `setBackgroundColor`, `setBottomBarColor`.

**6.3. Страница товара — премиальность:** свайп-галерея; блок «Пирамида аромата»;
характеристики (время горения, вес, воск) плашками; выбор количества; отзывы (позже);
«поделиться» через `WebApp.switchInlineQuery`/share.

**6.4. Микро-детали дороговизны:** параллакс-шапка фото при скролле; sticky-итог в корзине;
тактильная отдача на всех ключевых действиях; единая система отступов/типографики (мелкие
`text-[9px]…[10px]` — проверить контраст WCAG AA); оформленные пустые состояния.

**6.5. Шрифты:** `Bahnschrift` тянется с `cdnfonts.com` (ненадёжный CDN), Manrope и Material
Symbols — с Google Fonts. В Telegram-webview риск «прыжка» и задержек. → Self-host (`woff2` в
`public/fonts`) + `font-display: swap`. Быстрее, надёжнее, убирает внешние зависимости (важно для CSP).

**6.6. Навигация:** иконка «поиск» на Home (`Home.tsx:76`) просто ведёт в каталог — либо
открывать поиск с фокусом, либо убрать.

**6.7. Доступность (a11y):** `aria-label` иконочным кнопкам; осмысленные/пустые `alt`;
контраст `text-sub` (#8C867D); фокус-стили.
